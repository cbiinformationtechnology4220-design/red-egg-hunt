# Red Egg Hunt

This directory is an isolated React/Vite application for the Red Egg Hunt promotion. Winning physical cards use the canonical public URL. Participants enter their name, mobile number, and the eight-digit code printed beside the QR. All 50 approved printed codes are winning codes, and a successful submission consumes a code exactly once. Bokya cards use a separate branded path that shows the false-alarm message without displaying a form or collecting participant data.

The public URL is the exact canonical origin:

```text
https://red-egg-hunt.vercel.app/
```

The two physical QR destinations are:

```text
Winning egg QR: https://red-egg-hunt.vercel.app/
Bokya QR:       https://red-egg-hunt.vercel.app/bokya
```

The `/bokya` page uses the same Red Egg Deli interface but only shows the bokya message. It does not call the campaign-status API, display the participant form, or collect a name or mobile number.

## Current architecture

- Vercel serves the public page and the protected staff page.
- Vercel API routes proxy server-side requests to a Google Apps Script web app.
- Google Apps Script is bound to a private Google Sheet and is the durable source of truth.
- Apps Script uses `LockService` around code submission and staff claims; public reads do not wait behind a mutation lock.
- The browser never receives the Google Apps Script shared secret or direct Sheet access.
- The Sheet contains the approved 50-code inventory, private participant fields, state, and privacy-safe audit rows.
- No QR is generated by this application. Physical materials must use the correct winning or bokya destination above.

## Local commands

From this directory:

```sh
npm install
cp .env.example .env.local
npm run lint
npm run typecheck
npm test
npm run test:backend
npm run build
npm run dev
```

Local mock mode uses a synthetic all-winning 50-code inventory. It is for tests only and must never be printed or used as production inventory.

## Google backend setup

See [Google Sheets backend setup](docs/GOOGLE-SHEETS-BACKEND.md). The authorized operator must:

1. Create a private campaign spreadsheet using an approved resort Google account.
2. Bind an Apps Script project to the spreadsheet.
3. Run `initializeWorkbook()` once.
4. Set the `SPREADSHEET_ID` and `RED_EGG_SHARED_SECRET` Script Properties.
5. Add approved campaign settings to the `Settings` tab.
6. Add exactly 50 approved winning codes to the `Codes` tab.
7. Protect the spreadsheet and deploy the Apps Script web app.
8. Put the web app URL and matching shared secret into Vercel server-only environment variables.

Do not place real participant data, real codes, or shared secrets in Git, browser variables, screenshots, or chat.
